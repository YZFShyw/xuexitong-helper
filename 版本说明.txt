本轮修复（2026-10-25｜多选题）
------------------------------------------------------------
一、【多选题点了但没选中】
   症状：同一章 12 道多选，9 道「点了但没选中」、3 道「已选中」；失败的全是 2 或 4 个字母的答案，
        成功的全是 3 个字母。单选一直正常 —— 这个过于整齐的分布就是线索。

   根因① 坐标塌成一个点（fillAct 的 topCoord）：
      原来算每个选项之前都 el.scrollIntoView({block:'center'}) 再取矩形中心，
      等于把 4 个选项轮流滚到视口正中，算出来的坐标是**同一个点**（真页面实测都是 519,480）。
      于是「点 4 次」= 同一个点 toggle 4 次：偶数个答案一个都没点上，奇数个只点上一个。

   根因② isOn 串到兄弟选项：
      isOn 原来往上找 4 层，并且在祖先上 querySelector('.check_answer_dx')；
      多选结构是 LI > UL.Zy_ulTop > DIV.clearfix > DIV.TiMu，第 4 层正好是 .TiMu
      → 捞到兄弟选项的标记。只要本题有一个选项选中，四个选项全判成"已选中"，
      账面写「已选中：ABC」其实只点上一个，复查和记账跟着全错。

   改：
     · topCoord 不再滚动；新增 scrollBox() 只把**题目容器**滚一次，
       之后所有选项按同一个滚动位置算坐标（行距 51px 保留，点哪个是哪个）。
     · isOn 只认：自身 aria-checked/pressed → 自身内部 .check_answer* → 直接父级 aria
       （只 1 层、不做后代查询）。作业页那种"标记打在父元素 .workTextWrap 上"的结构照样覆盖。
     · 顺带：字母读不出来时按位置兜底，只落在 <li> 上（cands 里混着 .answer_p 会整体错一位）。

   验证：新增 tests/quiz-multiselect.test.js（4 条，带假滚动模型：坐标必须互不相同、isOn 不许串层）；
        做了变异验证（把两处改回旧写法，2 条立刻红）；全套 477/477（26 个文件）；
        真机受控点验第 11 题：点 A、B 两个都变 true，再点回去还原 false，页面状态复原。

本次补充（2026-10-28 ~ 10-30）
------------------------------------------------------------
一、【图题不再硬猜：告诉模型"这次没有配图"】
   实测（计算思维作业 30 题）：16 道带图，模型只拿到文字，却照着"下图是…"硬编，
   理由还写"由图可见"—— 它并不知道图没跟过来，整份作业错误率因此极高。
   改：送题时末尾加一句「本次只发送了文字，没有配图；题干要求看图的，请第一行只输出「不确定」」。
   实测：15 道图题当场主动弃权（1.3 秒/题），全部转入看图。

二、【请求超时 + 带图 → 也进看图兜底】
   原来只有"模型返回空"才登记看图；那 4 道题干很长、带图的题直接
   `This operation was aborted`（请求超时），落到 catch 分支只记欠账，看图永远轮不到。
   改：catch 里同样判断"带图 → 登记看图"，补不上才记欠账。
   实测：同一份作业「有 2 道题是图片题 ⇒ 走截图」→「补上 2 / 2 道 ✓」，30 题全部有答案。

三、【重做时别再命中旧答案】填作业.js 加 `--no-cache` / `--fresh`
   改了提示词想重做，结果 26 题直接「答案（缓存）」；加 `--no-cache` 后又变成
   「答案（题库·作业作答）」，命中的还是上一轮写进库的旧答案。
   `--fresh` = 缓存和题库都关，全部重新问模型（实测：题库命中 0 / 缓存命中 0）。

四、【填考试】新增 填考试.js + 网页控制台「考试页」入口
   考试页一页一题、靠「下一题」翻页，驱动器不认它。新脚本按显示字母对位点选项、
   每题回读 #answer 校验、**没有任何提交动作**。用法：
     node 填考试.js --dry            只看当前题 + 问一次 AI
     node 填考试.js                  从当前题往下填（跳过已答）
     node 填考试.js --force          连已答的也重填（会先取消多选里答案没有的选项）
     node 填考试.js --check --from=1 只核对整卷：打印空的 / 多选只填一个
   注意：最后一题的答案只存在页面内存里（没有「下一题」触发保存），填完别刷新，直接交卷。

五、【思维档位与输出配额可调】（2026-10-31）
   以前写死在代码里：恒开思考、reasoning_effort 恒 max、max_tokens 恒 32000，想快想省都只能改代码。
   现在「答题设置.json」多了两个字段，网页控制台「答题设置」页里能直接调：
     thinkMode：off / low / medium / high / max（默认 max）
     maxTokens：输出上限（含思维链），默认 5000
   放课那条链（逐题问 / 抄录后问 / 看图作答）和 填考试.js 读的都是这一份。
   注意：**抄录那一步故意不跟档位**，始终 medium —— 它要的是"把图上的字认全"，
   2026-10-19 实测过 high 会把配额烧掉一半、抄录被截断（当时整章不填就是它害的）。
   配额怎么定：单题 5000 有 4 倍余量（实测一道题思维链 1081 token、正文 34 token）；
   批量问 5~10 道时如果出现"最后一道题没答案"，就是配额不够，往上调到 8000~32000。

六、【填考试两处修复】（2026-10-31）
   ① 「模型没返回正文」：整场 50 题里 #33、#39 两道多选正文为空 —— max_tokens 被思维链吃光。
      改：配额读配置（见上），并且"退回"只对 API 400（参数不认）生效；
      401/429/超时原样抛出，不再伪装成"模型没返回正文"。
   ② 多选只填一个：题型字符串差一个字（页面写「多选题」、parseAnswer 只认「多选」），
      已加 normType() 归一；另外点击前检查 aria-checked，已选中的不再点（多选是 toggle）。

    ② 预算回血：只要视频确实在前进，本章"拦页轮数"清零 —— 轮数只量"连续卡了多久"，
       换卡/起播的瞬时毛刺不再把预算吃掉（实测：多卡章一次停留把每张卡播到平台完成线）；
    ③ 消息如实：平台标记完成但视频未到片尾时，日志改说"本节完成（平台标记，视频未到片尾）"，
       不再谎报"视频播完"。

四、【拉卡节奏】"在播就别拉"加了 20 秒容错；同卡试满 5 次进冷却（同第一节③）。

五、【答题接口超时】正文读取不再脱离保护（外部复核查出，已修）
    原来超时只护到"响应头到手"，正文（json/text）裸奔 —— 服务端拖正文/慢速滴流时
    会长时间挂着。现在定时器护到正文读完；同型三处全修（答题助手 / 图片指纹 / 配置自检），
    并加回归测试（本地假服务器模拟"拖正文/滴流"）钉住它。

【自检】工程目录：`node tests\run-offline-tests.js --no-pause` —— 22 文件 / 434 用例 / **0 失败** ✓
        分发包自带同一套 tests\，解压即可复跑；包内会有 1 项"设计内跳过"
        （「分发包里没有 _实验\，跳过」—— 正常，见代码注释）。

本轮修复（2026-10-12 收到《学习通助手-0.2测试反馈-20261012》）
------------------------------------------------------------
① 【高】题库码**只导一次**时，两张查询索引没重建（alias/order 还是导入前那份）
   —— 表现是"该命中却没命中"，**全程不报错**，最难查。
   根因：导入走的新增分支改了 `entries`，可内存里那两份反查表还是解析时建的；
   而写文件的 `serializeBank` 只是裸的 JSON.stringify ⇒ 落盘的是旧表。
   现在：**写文件之前无条件重算**派生索引（`rebuildDerived`），落盘的永远和 entries 自洽；
   顺带补上"新增分支漏了 official 标记"（官方答案在多来源时优先的那一档）。
   自检：导完一次，用清单里那段 PowerShell 对账 —— `alias 索引 == 条目里带 fpAlt 的`、
   `order 索引 == 条目里带 fpOrder 的`（注意：同一把顺序键撞车的不建索引，所以后者可能略少）。

② 【高】离线自检偶发红（`quiz-shot.test.js` 的"工作区文件没被碰过"）
   根因：同一轮里别处有路径绕过测试自己的临时隔离，碰了工作区的 答题答案缓存.json。
   现在：测试子进程的**默认缓存路径**被一个环境变量指到临时文件（产品只**读**这个变量，
   不写任何用户环境变量）；另外 runner 会**逐文件点名** —— 哪个文件碰了工作区那份，直接标红那个文件。

③ 【中】判断题答案口径不统一：`answer=B` 与 `answer=错` 被当成两个答案 ⇒ 假冲突。
   （判断题的选项就是 A.对 / B.错，两者语义相同；全库只有 6 条用字母。）
   现在：**读库和写库两个口子都归一**（判断题一律存正文 对/错），归一后重复候选自动合并、
   假冲突标记自动摘掉；导入报告里单列一档 `normalized`，不混进 `conflicted`。

★ 1) 替身字体能不能免费解开（这一版的核心）

★ 2) 题库命中：库里有的题不该再问模型
   现象：日志出现

   ⚠ 第一次跑必然是 0 命中（库里还没有那些题）——**要先跑一遍，再跑第二遍**才看得出效果。

★ 3) 题目进不进库（记录 → 库）
   现象：跑完几章后，看控制台「题库」那一栏：条目数在涨；

   期望：不用手动做任何事，库会自己长大。
        （这一版还多了"按课程分流"：日志里会有"另按课程分流 M 条到 K 个课程库"，
          控制台库清单里会出现以课程名命名的子库。）

★ 4) 带图片的题（公式图）
   现象：日志出现 → 图片指纹：xxxxxxxx | yyyyyyyy
        题面里的图会被算出一个 8 位短 id，写进记录，随后进库（条目带"图 N 张"）。
   期望：同一道带图题第二次出现时，走「答案（题库·…）」，**不再问模型**。
   如果看到 → 库里有这道题，但图片指纹对不上（…）→ 不用（怕填错题），走原路
       把这一行抄回来 —— 这说明"图变了"，是保守拒绝，不是错误，但我们想知道。

★ 5) 题目和选项的"身份"对不对（第二遍跑重点看）
   现象：题干里带题号（"3"）、带【单选题】标记的，第二次应该照样命中。

   期望：同样会记题、同样会查库、同样只点「暂时保存」，**永不点提交**。

★ 8) API 网关地址可以自定义了（默认还是 DeepSeek）
   以前接口地址是写死的（api.deepseek.com）。现在多了一个配置项 apiUrl，
   想走中转/自建网关就填对方给的**完整地址**（很多网关是 /v1/chat/completions 结尾）。
   怎么改（三种都行）：
     · 控制台页面上「网关地址」输入框 → 填 → 【保存 key】（同一个按钮一起存）
     · 控制台【网关恢复默认】按钮 → 一键回到 DeepSeek 官方
     · 命令行：node 配置.js --set apiUrl=https://your-gateway.example/v1/chat/completions
              node 配置.js --set apiUrl=default      （恢复默认）
   规则：必须以 http:// 或 https:// 开头，写错会**当场拒绝**并告诉你原因（不会把 key 发到奇怪的地方）；
        没填/填错 = 回落 DeepSeek 官方。控制台和日志里显示这行时，URL 的查询串会被打码

★ 9) 题库可以"按标签导出"（冲突 / 官方 / 带图 …）

   怎么用：
     · 控制台「题库」栏 → 下面一排勾选框（每个标签后面标着"这个库里有几条"）→
