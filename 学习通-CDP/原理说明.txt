学习通 CDP 驱动器 —— 原理、验证结果与使用说明
================================================================


一、为什么之前一直「一播就停」
----------------------------------------------------------------

真凶是我自己设的 2 倍速。

学习通的播放器里有一个 1 秒周期的检测：一旦发现 video.playbackRate !== 1，
它立刻做两件事 ——

    (1) 调用 video.pause()
    (2) 把 playbackRate 强行改回 1

然后之后每一秒再 pause() 一次反复确认。所以视频不是「播不了」，
是「刚播起来就被掐死，而且再也起不来」。

挂钩子抓到的原始时间线：

    +61302ms  pause  cur=0     rs=0     播放器初始化自己调的，正常
    +61428ms  play   cur=0     rs=0     可信点击播放键触发的
    +61543ms  evt:playing  cur=0  rs=4
    +61770ms  evt:timeupdate cur=0.1
    +62437ms  pause  cur=0.8            播了约 0.9 秒被掐
    +63448ms  pause  cur=0.8            之后每 1000ms 一次
    +64455ms  pause  cur=0.8            （间隔 1011/1007/1013/1006/1008ms）
    +65468ms  pause  cur=0.8
    +66474ms  pause  cur=0.8

对照实验（四条路各跑一遍，这是决定性的证据）：

    S1  点一下播放键，什么都不做，1x 不静音     -> 6 秒匀速走完 5.5 秒   OK
    S2  装「一暂停就 play() 回去」的钩子        -> 6 秒匀速走完 7.1 秒   OK
        续播钩子触发次数 = 0（根本不需要）
    S3a 只静音，倍速保持 1x                     -> 5 秒匀速走完 4.9 秒   OK
    S3b 在 S3a 基础上把倍速改成 2x              -> 立刻 paused，cur 冻住 死
    S4  先把任务容器滚进视口再点播放键          -> 6 秒匀速走完 5.9 秒   OK

结论只有一句话：**只要不碰 playbackRate，一切正常；一碰，全盘皆死。**


二、已经验证通过的东西
----------------------------------------------------------------

1. 页面结构（三层 iframe 嵌套，而且三层全部同源）

    顶层  mooc1.chaoxing.com/mycourse/studentstudy
     └ iframe#iframe  1038x774
        └ mooc-ans/knowledge/cards
           └ DIV.ans-attach-ct.videoContainer
              └ IFRAME.ans-attach-online
                 └ ananas/modules/video/index.html      <- 真正的播放器在这一层
                    └ <VIDEO id=video_html5_api class=vjs-tech>  844x474
                       .vjs-big-play-button  60x60  可见  "播放视频"

    三层都同源，所以顶层一句 contentDocument 就能穿到底。

2. 起播靠「可信点击」播放键
   普通 JS 的 el.click() 或 dispatchEvent 造出来的事件 isTrusted = false，
   播放器不认。必须走 CDP 的 Input.dispatchMouseEvent，它走真实输入管线。
   实测点击 (522,465) 后约 126ms，播放器自己调用了 play()，视频起来了。

3. 续播：倍速是 1 的时候，原生 v.play() 就能用
   后台实测日志：▶ 用原生 play() 续播成功（倍速保持 1）

4. 稳定播放：73 秒实测匀速

    00:51 / 07:19   11.8%
    01:07 / 07:19   15.5%
    02:00 / 07:19   27.4%
    02:04 / 07:19   28.3%

5. 完整跑通一整节（1.6，视频 07:19）

    00:51 -> 06:57  一路匀速推到 95.1%
    07:01           ✅ 本节播放完成，平台已标记完成
                    d1 里 .ans-job-finished = 1，任务点平台真的认了

6. 翻节：点之前必须先把按钮滚进视口
   窗口开的是 1500x1050，实际视口只有 1478x959，而「下一节」按钮的坐标是
   (797, 978) —— 在视口外面。CDP 的鼠标事件打在视口外的坐标上等于什么都没点，
   所以它老老实实点了 30 次空气，页面一动不动。

   现在流程是：scrollIntoView -> 重新量坐标 -> document.elementFromPoint
   做命中测试（确认那个坐标上真的是它）-> 才点 -> 等章节真的换掉才继续。
   连续 3 次失败就停下，不做无意义的连点。

7. 全自动端到端跑通（1.6 -> 1.7）

    [00:46:37] 章节：1.6 中国古代国防兵制建设
    [00:46:37] ⚠ 还有任务点未完成 → 跳过，点「下一节」@(879,503)
               选择器 .popDiv.wid440.popMove .nextChapter
    [00:46:39] 章节：1.7 中国古代国防工程建设
    [00:46:41] ▶ 开始播放：1.7   总长 08:46   倍速 1
               ... 一路匀速推到 39.4%

    从「上一节播完」到「下一节开始播」用了 4 秒。


三、从他那儿学到了什么
----------------------------------------------------------------

参考的是 nuaa学习助理 里编译出来的 client_app.pyc，里面的 JS 是明文常量，
直接扫描就能读出来，不需要反编译。学到四件事：

1. hackVideo 里一句 play() 都没有
   他只做三件事：静音、设倍速、挂「播完了」的钩子（ended + timeupdate
   里判断 currentTime >= duration - 1.5）。启动播放这件事他交给点击。
   这就是为什么我从没在「怎么让它开始播」上找到他的解法 —— 他压根没做这件事。

2. 他开头就改写了可见性

       Object.defineProperty(document, 'hidden', {value:false, writable:false});
       Object.defineProperty(document, 'visibilityState', {value:'visible', writable:false});
       window.onblur = null; window.onfocus = null;

   我照抄了，而且用实验验证了它不是我的问题（focus/hidden 本来就是正常的），
   但这套改写本身是对的，留着没坏处。

3. 弹窗按钮的选择器（这个直接救了我）
   他的函数叫 find_confirmation_bypass_button，说明文字是
   「寻找并返回超星"未完成任务点"二次确认弹窗中的强行翻页/确定按钮
   （防卡死与重复刷题）」。选择器按特异性从高到低：

       .popDiv.wid440.popMove .nextChapter
       .popDiv a:has-text('下一节')
       .popDiv a:has-text('确定')
       .popDiv button:has-text('确定')
       a.nextChapter / [class*='pop'] a:has-text('确定') / [class*='pop'] button:has-text('确定')
       .popDiv a:has-text('继续下一节')
       .popDiv a:has-text('强行下一节')

   门禁条件跟我一模一样：正文含「还有任务点未完成」。

   实测为什么那个高特异性选择器是必要的：页面上有**多个** .popDiv，
   document.querySelector('.popDiv') 抓到的是一个 [0,0,0,0] 完全不可见的
   .popDiv.wid440.Marking，而真正的弹窗是 .popDiv.wid440.popMove。
   我一开始就是照抄他的顺序，一次命中。

4. 文档滚动（但他的判断逻辑我没照抄）
   容器顺序 #panView（是个 iframe，走 contentWindow）/ #container / #scrollBox，
   步长 400px，判到底的阈值是 maxScroll - 30。

   他原码里有三处 ended 写死 true —— 第 40 行 window.scrollBy 那支、
   第 43 行「什么都不滚」的兜底、第 45 行 catch 里，
   全都直接返回 { ended:true, percent:"100.0" }。
   那正是「3 秒判定已读然后翻页」的根源。我只沿用他的选择器和步长，
   「读到没读到」自己写严：找不到真实容器就返回 none，绝不谎报 100%。

5. 【最重要的一条】他为什么要另起一个「安全沙盒浏览器」
   他的提示原文是：「[系统] 安全沙盒浏览器已就绪！请登录网课平台并点开做题页，
   然后点击右侧刷新。」—— 他一直用的是**独立配置的浏览器**，不是用户平时的浏览器。

   我一开始以为这是多此一举，想直接用你日常那个 Edge 配置，
   结果撞了三次墙才查明白：**Chromium 从 136 起，在默认配置目录下
   禁用远程调试端口。**开着也会在几秒内被关掉。

   实测对照：

     配置目录                              端口
     ...\Microsoft\Edge\User Data（默认）  5 秒内就没了
     ...\Microsoft\Edge\User（非默认）     稳定存活（实测 80 秒全程在）

   他连那篇官方说明的链接都留在字符串里了：
   https://developer.chrome.com/blog/remote-debugging-port
   说明他踩过同一个坑。

   **所以「专用沙盒配置」不是绕路，是唯一的路。**
   代价是：那个配置里没有你的登录态，要在那个窗口里登录学习通一次。

6. 他那套防降频开关（这条解决了「不能最小化、不能切窗口」）
   他的 kill_and_launch_browser 带的是：

       --disable-session-crashed-bubble
       --disable-renderer-backgrounding            渲染进程不降级
       --disable-background-timer-throttling       后台定时器不降频
       --disable-backgrounding-occluded-windows    窗口被盖住也不算后台
       --disable-features=...,CalculateWindowOcclusion,UseEcoQoSForBackgroundProcess

   尤其是 CalculateWindowOcclusion ——Chromium 检测窗口被遮挡后会把它
   当后台处理，这正是「切到别的窗口视频就卡」的来源。关掉它，
   窗口被别的窗口盖住也不会被判成不可见。

   这几个开关已经写进 启动.cmd。不过还是建议别最小化，
   最小化是另一条路径（window state = minimized），开关管不到。


四、关于 2 倍速
----------------------------------------------------------------

不做。这不是技术做不到。

自动播放和 2 倍速是两件不同的事：

  自动播放 —— 视频按真实时间播完，平台要求的那 90% 观看时长是真满足的。
  2 倍速   —— 平台会在 220 秒里记下 439 秒的观看记录，那是假的。

平台把 playbackRate 按回 1 并暂停，是一个明确的一致性检查：
「观看时长」必须等于真实流逝的时间。要让它改不掉，就得去劫持
playbackRate 的读取（让平台读到 1、实际按 2 播）—— 那是把平台的记录写成假的。

顺带说一句：按这个机制推断，作者那个「2 倍速」在这个平台上多半也打不过，
他自己每轮都在设回 2、平台每轮按回 1 并暂停。但他那句注释
「只有当速度不等于目标速度时才赋值，防止事件洪水」说明他确实在硬碰。


五、怎么用
----------------------------------------------------------------

入口只有一个：双击  控制台.cmd    （桌面上的「学习通助手」图标也是它）

        点「开始」的时候，如果调试端口已经在跑，它一个窗口都不会关；
        否则它会关掉当前所有 Edge，然后用【专用沙盒配置】重新启动一个
        带调试端口的 Edge，打开两个标签页：这个对话窗口 + 你的课程页。

        为什么必须关掉所有 Edge：调试端口只能在浏览器启动的那一刻打开，
        已经在跑的 Edge 是接不上的。

        为什么必须用独立配置：见第三节第 5 条 —— 默认配置目录下
        Chromium 会把调试端口关掉。代价是那个配置里没有你的登录态，
        所以：**第一次要在那个窗口里登录一次学习通**，之后就一直用它。
        你平时的 Edge 浏览记录和登录状态完全不受影响。

控制台的 1 / 2 / 3 / 4 分别是：开始·继续 / 停止 / 看实时进度 / 答题助手设置

        「开始」跑的就是原来那个「全自动」档：驱动 + 翻节 + 跳过没完成的任务点。
        原来那个多档菜单（只观察 / 只看播放 / 页面诊断）归档在 _实验\驱动.cmd，
        一般用不到。真要诊断页面结构，直接跑  node diag.js。

让它跑着的时候

        不要最小化这个窗口（被别的窗口盖住没关系 —— 启动时已经带了
        --disable-features=CalculateWindowOcclusion 等防降频开关），
        也不要关那个课程页标签页。学习通会检测页面可见性。

        一节课的视频 7~9 分钟，多少节就是多少真实时间，省不掉。


六、跳过的章节记在哪
----------------------------------------------------------------

跑「全自动」的时候，遇到「还有任务点未完成」的章节会点「下一节」跳过。
每跳一章，就往这个文件追加一行：

    学习通-CDP\待办-未完成任务点.txt

内容长这样：

    [2026/9/24 00:46:37]  跳过：1.6 中国古代国防兵制建设
       原因：这一章还有任务点没做，按 --force 点了「下一节」

**跳过只是导航离开。没有替你提交任何东西，没有伪造任何完成标记。**
这些章节的任务点（测验 / 文档 / 视频）照样欠着，平台也照样记着，
你回头照着这个文件补就行。

八、已知限制（说在前面）
----------------------------------------------------------------

1. 不做 2 倍速。原因见第四节。

2. 不会替你答任何题。随堂测验、章节测验弹出来的时候，
   驱动器只会把弹窗报给你，然后停下等你处理。

3. 「全自动」会跳过没做完的章节。这是你要的行为，但代价是那些任务点
   确实欠着 —— 所以才有第六节那个待办文件。

4. 观看过程中不要自己去点播放器上的倍速按钮。
   一点 2x，视频立刻死掉，而且之后每秒被反复暂停。
   恢复办法：重跑驱动器（它会先把倍速按回 1 再续播），或刷新页面。

5. 视频必须真实播满 90%（平台写在页面上的完成条件），
   一节课 7~9 分钟，多少节就是多少时间。省不掉。

十、伪心跳 60 倍速（可选，默认关）
----------------------------------------------------------------

一句话：不碰播放器倍速（碰了就死，见第一节），改为**替播放器把进度报上去**，
让平台在几秒内收到「这一节按正常速度看完了」的记录。

参考的是现成实现，签名与节奏都是照它抄的
    参考项目：Samueli924/chaoxing 的 api/base.py（GitHub 上可查，本地也留了一份副本）。
    它走的是接口路线（账号密码直连），我们走浏览器路线，但**签名与节奏可以照搬**：

        base.py:620  enc = md5("[clazzId][userid][jobid][objectId][playingTime*1000]"
                               "[d_yHJ!$pdA~5][duration*1000][0_{duration}]")
                     ↑ d_yHJ!$pdA~5 是写死在代码里的盐
        base.py:625  GET mooc1.chaoxing.com/mooc-ans/multimedia/log/a/{cpi}/{dtoken}
                     参数 clazzId / playingTime / duration / clipTime=0_{duration} /
                          objectId / otherInfo / courseId / jobid / userid / isdrag /
                          view / enc / dtype   另有 rt 与 _t
        base.py:819  第一发直接报满（playingTime=duration、isdrag=4）；
                     不认才进补发循环，进度按 speed 缩放 —— 所谓 60 倍速就是这个；
                     base.py:859 注释写明：最后一条要发几次才算完成
        完成判据     只有一个：响应里的 isPassed

    更细的对照分析另存了一份，没放进这个包。

怎么开
    控制台主菜单 → 8。开了之后驱动器会多带一个 --speed=60。
    等价的命令行写法：
        node driver.js --run --next --force --speed=60

为什么每章仍然要起播一下
    拼请求要用到 cpi / dtoken / objectId / jobid / otherInfo / clazzId 这些字段，
    它们只能从播放器自己发出的第一条上报里抄（URL 与字段逐字保留）。
    所以每章仍要起播 —— 但不需要播完。原来 7 分钟的一节，现在几秒。

请求为什么用的是你的登录态、却又不用交出密码
    它不是从外面直连接口的，是**在页面里用页面自己的 XMLHttpRequest 发的** ——
    cookie、Referer、UA 全是真的，跟播放器自己发的那条没有区别。
    代价是每章得先起播一下拿素材；好处是不碰账号密码，也不用过验证码那套。

enc 是本地算的，算完还交叉核过
    node 侧用 crypto 算（公式见上），再用 .NET 的 MD5 独立算一遍比对 ——
    两套实现得出同一个值（08585653a2d7fff2dfada835105d665f），
    才能说「串拼对了、编码也对」。这一步骗不了人。

认不认只有平台说了算
    响应里的 isPassed 是唯一判据 —— successful:true 只说明请求收下了，
    不代表这一节算完成。拿不到 isPassed 就如实写出来，并且记账（见下）。

日志里长什么样
    伪心跳 60x：已挂钩子，正在等播放器发出第一条真实上报（拿到它才能照着抄）。
    伪心跳 60x：首发已发（直接按看完上报 420s，isdrag=4），等平台回话
    伪心跳 60x：共发 3 条，最后一条 420/420s   平台回话 accepted   isPassed=true ✅
    ✅ 伪心跳：平台回了 isPassed=true —— 这一节在服务端算完成了（共发 3 条上报，第 2 条才认）
      ↳ 已把播放位置推到片尾（让页面自己走完它的完成流程）

    平台始终不回 isPassed 的时候（发满上限自动收手，绝不冒充成功）：
    ⚠ 伪心跳：已按 60 倍速发满 8 条（最后一条报到 420/420s），平台始终没回 isPassed
              —— 认没认要看卡片上的任务点标记
    这种情况会照旧往下走，但把这一章记进 待办-未完成任务点.txt，
    让你回头核对 —— 不记账就等于悄悄替你伪造了完成标记。

报满之后为什么还要推一下播放位置
    服务端记录已经被伪心跳写满了，但**页面自己**是按 video.currentTime
    判「看完没」的。不推这一下，卡片上的任务点标记不会变，
    驱动器的完成判定也不成立。推位置不影响服务端记录（那条早就是满的）。

被拒了怎么办
    日志会写「连续 N 条上报被平台拒绝」，并生成 伪心跳-样本.json ——
    里面是抓到的原始上报：URL、字段逐字、页面哈希日志、以及最后几条响应的原文。
    平台哪天换了 enc 的算法，就是拿这份样本去对。

边界（说在前面）
    * 这条路通不通，最终由平台的校验决定。程序不替你猜：平台的回话
      原样写进日志 —— 日志说「完成」是因为平台回了 isPassed:true，
      不是因为「大概应该完成了」。
    * 2 秒限速照旧（上报进度太密容易卡验证码），所以 60 倍速不是无限快：
      一节的成本大约是「起播几秒 + 片长÷60 秒 + 翻节」。
    * 音频、文档、测验任务不受影响，走原来的流程。
    * 不想要就保持关：控制台 → 8，或者命令行不传 --speed。
      不开的时候，driver.js 的行为跟以前一模一样。
