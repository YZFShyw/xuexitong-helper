二、结论：video-js 播放器挂在哪一条分支上
--------------------------------------------------------------------------------
  顶层  studentstudy（#iframe 的宿主）
   └─ #iframe                                    → /mooc-ans/knowledge/cards     （知识卡片页，d1）
        ├─ iframe.ans-attach-online.insertdoc-online-pdf    → /ananas/modules/pdf    ← 先出现的岔路，没有播放器
        └─ iframe.ans-attach-online.ans-insertvideo-online  → /ananas/modules/video  ← ★ 播放器在这一支
             └─ div.video-js.vjs-default-skin > video.vjs-tech  ← 真正的 <video>（844x474）

  关键事实：两个卡片 iframe 是**兄弟节点**，class 前缀一模一样（都是 ans-attach-online），
  而 PDF 卡片在 DOM 里排在前面。所以"取第一个匹配 ans-attach-online 的 iframe"
  必然一头扎进 PDF 那一支 —— 那一支里连 .vjs-big-play-button 都不存在。

四、这次的改动（driver.js）
--------------------------------------------------------------------------------
  1) chain() 下降顺序改成"按哪一支可能是播放器"排：
       iframe.ans-insertvideo-online  >  id/src 含 video  >  音频卡  >  文档卡  >  兜底
     这样才会跟着播放器那条分支走，而不是撞上第一个同前缀的兄弟节点。
  2) 走错支路不再默默返回 null：chain() 带回 f2sel / depthReached / d2，
     PROBE 把"走的哪条支路、落到哪个文档、各路 iframe 里有几个 video/播放键"一并报回日志。
  3) 补上"把播放器滚进视口"：PROBE 先 scrollIntoViewDeep() 再量坐标，
     并给出 seesBigPlay / seesArea 标记。
  4) 视口外的坐标一律不点；续播改成按优先级逐个候选试（大播放键→控件栏播放键→画面→容器），
     每点一次立刻回读确认是否真的播起来。
  5) PROBE 加了顶层保护：不是顶层文档时直接返回 {notTop:true}，
     不再把内层 iframe 的坐标当成顶层坐标报出来（那会得到 422,237 这种"看着正常其实是错"的数）。

五、第二轮：用户反馈"视频做完、题没做，它把题一起跳了"
--------------------------------------------------------------------------------
  对比了归档里的原始脚本（_旧版与归档\学习通助手.user.js），差别在**怎么判"这一章做完了"**：

  原始脚本（第 1750-1777 行）：
      const all = taskContainers();          // 这一章所有任务点
      const pending = pendingTaskPoints();   // 逐个看哪些没带完成类名
      if (!pending.length) return goNext('任务点已全部完成');
      if (!all.length) return;               // 没找到任务点 ≠ 做完了，绝不翻页
    它还有一条明确写下的教训（v2.4）："一个任务容器都没找到，绝不等于任务点全做完，
    旧版把这两者混为一谈，于是看不见任务点时就直接翻页，成了无限跳章。"

  我们的 driver.js 却是一句全局判定：
      o.platformDone = querySelectorAll('.ans-job-finished, .ans-job-finish').length > 0;
    意思变成"这一章**任意一个**任务点完成了 = 整章完成"。学通一章可以有多个任务点
    （视频 / 文档 / 测验 / 作业），视频做完就整章翻页 —— 题目那个任务点连碰都没碰。
    这就是"把题一起跳了"。

  改法：
   1) platformDone 改成**逐个任务点**判：数 total/done/pending，
      只有 pending===0 才叫全绿；并单独回答"装着视频的那个任务点完成了没"。
      PROBE 还会把"还没做的是哪几类"（视频/测验/作业/文档）报回日志。
   2) "视频已完成"那条分支以前**根本不调 tryQuiz**，直接 advance 走人。
      现在不管视频是"播完的"还是"平台已标记完成的"，都**先交代这一章的测验**，
      再做文档、最后才翻页。顺序也调了：以前是"先滚文档 → 直接 advance"。
   3) 加了"这一章的测验做过了吗"判定（照原始脚本 isQuizDone 的三重判定：
      正文有已答痕迹 / 作答控件全 disabled / 有判分标记），做过的绝不重填。
   4) 答题助手说"没填上"的时候，不再当成"做完了"：只有真的
      "已按顺序填进页面"才算 handled；只开了页面没填上叫 opened，
      照旧记进待办（待办里会写"测验打开过但没填上"）。

六、顺带修掉的三个坑（都是实测撞出来的）
--------------------------------------------------------------------------------
  a) 卡片页卡在"章节测验"栏（&num=1）：那一栏**没有视频卡**，驱动器就一路判"没有可播内容"，
     又去开测验，原地打转。原因是标签页切换用了合成 MouseEvent，对
     <li onclick="changeDisplayContent(...)"> 不生效。现在改成三招挨个试
     （el.click() → 合成事件 → 直接求值 onclick），并且**用 src 里的 num 验证到底换没换**；
     另外每轮自愈：发现 num=1 且那一栏没题，就自己切回"章节"栏。
  b) 弹窗点不动 + 遮罩：那个"还有任务点未完成"弹窗上盖着一层全屏遮罩
     （maskDiv jobFinishTip，1470x959，z-index 999）。算出来的坐标
     (797,849)、(805,704) 命中的全是遮罩，不是按钮 —— 实测 88 次点击，
     弹窗一次都没消失过。而且弹窗里有些时刻压根没有「下一节」按钮。
     现在点完**回头验一次**（弹窗还在 + chapterId 没变 = 点不动），连着两次就停下并说清原因。
     曾经想用页面自己的 PCount.next 硬绕，查了源码后放弃：
       PCount.next(count, chapterId, courseId, clazzid, knowledgestr, checkType)
     只有 cur >= count 才真的 POST /mycourse/changeCapter 换章，
     乱传参数只会把卡片切到测验栏（不换章）。硬绕等于伪造进度，不做。
  c) 答题期间主循环抢页面：tryQuiz 要跑十几秒（切栏、截图、问模型、填答案），
     这段时间主循环会一边判"这一章没内容"一边点「下一节」，等回头填答案时
     题目控件已经被翻走了（日志里"页面上共 0 题"就是这么来的）。
     现在答题期间主循环只等不动（quizBusy）。
